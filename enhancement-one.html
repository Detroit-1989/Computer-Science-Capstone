Enhancement One Narrative

Artifact: Travlr Getaways · MEAN-stack full-stack web application

Artifact Description

The artifact I selected for my Software Design and Engineering enhancement is the Travlr Getaways full-stack web application, which I originally developed in CS 465: Full Stack Development in 2026. The project was designed as a travel website that includes both a public-facing customer website and an administrative single-page application. The application features the MEAN stack, incorporating MongoDB, Express.js, Angular, and Node.js.

The application demonstrates a layered full-stack architecture. MongoDB offers persistent storage for travel packages and user information, while Mongoose provides the models used to interact with that data. Express.js and Node.js deliver the server-side application and RESTful API. Angular provides an administrative interface through reusable components and services. Together, these technologies allow information to move between the database, API, server, and client interface.

The administrative portion of the application also incorporates authentication and CRUD functionality. An authenticated administrator can work with travel packages by creating, retrieving, updating, and deleting records through the Angular interface.

For CS 499, I preserved the original Travlr Getaways project and created a separate enhanced version. This allows the original implementation and my enhanced artifact to demonstrate the progression of my software engineering abilities.

Justification for Inclusion and Improvements

I designated Travlr Getaways for my ePortfolio because it is one of the most comprehensive software engineering artifacts I developed during the Computer Science program. It proves more than the implementation of an isolated programming concept. The project required me to integrate front-end development, server-side programming, RESTful services, database persistence, authentication, and application security into a functioning system.

Several components demonstrate my software development abilities. The Angular application uses components and services to separate user-interface responsibilities from data-access logic. The Express backend uses routes and controllers to organize API functionality. Mongoose models define the structure of persistent data and provide an interface between the application and MongoDB. RESTful endpoints provide communication between the Angular client and server.

The authentication system provides another important example. Administrator passwords are not stored as plaintext. The user model generates random salt and derives a password hash using PBKDF2. During authentication, the supplied password is processed using the stored salt and compared with the stored hash. Successful authentication generates a JSON Web Token that the client can use when making authenticated requests.

For my enhancement, I improved the artifact by strengthening and validating the administrative workflow and organizing the application as a more portfolio-ready software engineering artifact. I reviewed the interaction among the Angular client, authentication services, Express API, controllers, models, and MongoDB database rather than treating each feature as an independent piece of code.

I also performed end-to-end testing of the application. I used Postman to verify registration and login functionality and confirmed that successful authentication returned a token. I tested the application's CRUD operations and used browser developer tools to inspect HTTP requests and responses. Successful POST, PUT, and DELETE requests demonstrated that the administrative application continued to communicate correctly with the REST API after authentication and security functionality was incorporated.

These improvements showcase my ability not only to write software but also to evaluate, test, debug, secure, and maintain an existing full-stack system.

Reflection on the Enhancement Process

Improving Travlr Getaways helped me recognize the difference between making individual features work and understanding a software system as a complete architecture. When I originally developed the project in CS 465, much of my attention was directed toward completing individual requirements such as creating Angular components, connecting MongoDB, implementing REST endpoints, and adding authentication. Revisiting the application during CS 499 required me to understand how those components depend on one another.

One of the most important lessons involved tracing data through the complete application. A request originating from the Angular interface may pass through a service, HTTP request, Express route, controller, Mongoose model, and MongoDB database before returning a response to the client. Understanding that sequence made troubleshooting more systematic because I could isolate the layer responsible for a problem rather than changing code without first identifying its source.

Testing reinforced this lesson. Postman allowed me to test the API independently from the Angular interface, while Chrome Developer Tools allowed me to inspect requests generated by the application itself. This helped me distinguish client-side problems from API or database problems. Verifying HTTP status codes such as successful 200 and 201 responses also provided concrete evidence that the application's operations were executing correctly.

Authentication was another important learning experience. Examining the relationship among password hashing, salts, credential validation, JSON Web Tokens, local storage, and protected requests improved my understanding of authentication as a process that spans multiple layers of an application. I learned that displaying a login form alone does not provide security; authentication must be enforced through the server-side architecture and the handling of protected API operations.

I also encountered challenges involving the development environment and source control. For example, when preparing the enhanced artifact for Git, Visual Studio's .vs directory contained local files that Git could not access and that did not belong in source control. I addressed this by configuring .gitignore to exclude development-environment files, node_modules, and environment files. This experience reinforced the importance of distinguishing source code from machine-specific files, generated dependencies, and potentially sensitive configuration data.

Finally, I preserved the original project separately from the enhanced artifact and used a dedicated cs499-enhancement-one Git branch for the completed enhancement. This gave me practical experience with maintaining an auditable development history and reinforced the value of version control when modifying an existing software system.

Overall, this enhancement strengthened my understanding of full-stack software engineering, authentication, testing, debugging, application architecture, and version control. More importantly, it demonstrated my growth from completing individual programming requirements toward evaluating and maintaining a complete software system.
